# Benchmarks, 2026-09-14

Machine: Intel Core i9-10850K (10 cores, 20 threads), Windows 10 Education 10.0.19045,
rustc 1.93.0, `onig-regset` 6.7.0, `profile.bench` (release, debug = 1).
Irosashi at `e9c19c0` plus the I5 working tree. Theme `github-dark` throughout.

Commands:

```bash
cargo bench -p irosashi-fidelity --bench highlight -- --save-baseline i5-before
cargo bench -p irosashi-fidelity --bench highlight -- --baseline i5-before
cargo run -p bench-report                      # markdown table from target/criterion
cargo test -p irosashi-fidelity --release --test alloc_audit -- --ignored --nocapture
cargo test -p irosashi-fidelity --release --test cold_start -- --ignored --nocapture
```

Criterion reports the mean; the tables below use the median from `estimates.json`
(`bench-report`). Nuri's numbers are its `tools/compare` warm medians on the same five
snippets (no-interrupt engine, June 2026, same machine class) and its cold first-call
times; Shiki's are from the same table. See section "Nuri rerun" for a same-day rerun.

the allocation fixes cannot touch that.

## After fixes

Fixes: dense injection hit lists without the per-step copy, memo `SetId` cached per
frame per line, unchanged-stack snapshot reuse, one capture buffer per session,
single-pass theming. Criterion against the `i5-before` baseline: 17 benches improved,
5 within noise or slightly regressed (all small snippets, differences under 3
percent). Full after table in `bench-final-table.md`, allocations in
`alloc-after.md`; per line on javascript medium: 21.9 to 7.8 allocations.
