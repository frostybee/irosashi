# Performance on Ferroni 2.7.0 (2026-11-08)

Raw dumps behind the tables in README.md and docs/content/docs/why-irosashi.md, all taken in
one session on an idle machine: Criterion (irosashi-fidelity, `cargo bench --bench highlight`),
the `cold_start` test, `tools/shiki-bench` (Shiki 4.4.3), and `tools/kazari-bench` (release
`kazari` 0.3.1, both engines). Inputs and method are unchanged from `2026-10-07-ferroni.md`;
only the regex engine changed (Ferroni 2.7.0 for 1.9.0). The README cold column is the
`first line ms` plus `rest of medium ms` columns of the `cold_start` table, as before.
Machine: Intel Core i9-10850K, Windows 10, rustc 1.94.0, Ferroni 2.7.0, Shiki 4.4.3, Node 24.12.0, theme `github-dark`.

Against the 2026-10-07 session: Irosashi warm large inputs are 1 to 26 percent faster (PHP
60.3 to 44.6 ms, JavaScript 91.1 to 82.2 ms, CSS 22.1 to
19.0 ms), small inputs within a few percent either way. Shiki's own numbers moved too,
on the same Shiki 4.4.3 and Node: JavaScript is about half of the October session at both
sizes and Go large is a quarter lower, which is the between-session variance the method note
warns about; the two engines are always compared within one session for that reason.
